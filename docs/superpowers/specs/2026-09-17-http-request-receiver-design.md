# HTTP 请求归档服务设计

## 目标

在服务器上提供独立 HTTP 接收服务，监听 `0.0.0.0:3100`。每一条经访问密钥验证的请求均按原样归档，便于后续审计或解析。

## 范围与约束

- 使用 Python 3 标准库，不新增第三方运行时依赖。
- 端口通过配置设为 `3100`；主机防火墙与 1Panel 放行由部署人员完成。
- 请求头 `X-Receiver-Token` 必须与配置的密钥以常量时间比较相等；不匹配返回 `401`，且不写入归档目录。
- 支持常见 HTTP 方法和任意路径；服务不解析 JSON、表单或文本内容。
- `max_body_bytes` 限制单请求正文。无效、过大或分块累计超过限制的正文返回 `413`，且不归档。
- 每个已认证且合规的请求使用独立目录，保存请求方法、目标、完整 URL、查询参数、HTTP 版本、来源地址、接收时间、所有非密钥请求头、正文长度、正文 SHA-256 和原始正文；空正文也保存为空文件。
- 归档可能含敏感内容。归档目录必须在发布目录外，并以操作系统权限限制访问；应用日志和 HTTP 响应不得回显正文或请求头。

## 架构与数据流

新增 `http_request_receiver` 包。`config.py` 读取并校验 JSON 配置，`archive.py` 原子写入单个请求目录，`server.py` 以 `http.server.ThreadingHTTPServer` 验证密钥、读取受限正文并归档，`main.py` 提供持续运行的命令行入口。

处理顺序为：接收请求、校验唯一的 `X-Receiver-Token`、检查正文长度、读取有限正文、建立请求 ID、写 `body.bin` 与 `request.json`、返回 `201` 和请求 ID。归档前会移除 `X-Receiver-Token`，其余请求头用有序数组保存以保留重复头。

```text
<storage_root>/requests/YYYY/MM/DD/<request-id>/
  request.json
  body.bin
```

## 配置与响应

配置文件包含 `listen_host`、`port`、`storage_root`、`receiver_token`、`max_body_bytes`。密钥必须至少 32 个字符，实际密钥绝不提交到仓库。成功返回 `201`；无效或缺少密钥返回 `401`；正文过大返回 `413`；意外归档失败返回 `500`，不泄漏服务器路径。

## 测试与部署

测试覆盖配置校验、认证失败不落盘、完整请求归档、空正文、重复头保留、密钥脱敏及正文超限。部署说明提供 1Panel/系统服务的运行、归档目录权限、固定密钥生成、端口防火墙限制和 `curl` 验收命令。
