# 标特福设备原始数据接收服务设计

## 目标与边界

本项目新增一个独立的 Windows 10 后台接收程序。它在局域网指定 IP 和 TCP 端口上监听设备连接，将收到的字节流按到达顺序持久化保存，并保留可审计的接收元数据。它不解析标特福 `.rot` 内容，不修改、转码、反序列化或去重原始数据，也不在首版调用数据库、HTTP API 或其它外部系统。

现有《标特福锣机采集参数》文档列出 `.rot` 文件中的加工参数和示例 FTP 地址，但没有定义网络传输协议、端口、帧长度或结束符。因此首版只实现可配置的 TCP 接收器；归档模型不依赖“设备发送完即断开”的假设。确认设备使用 UDP 后，可新增 UDP 监听器而不改变已保存数据的格式。

## 运行方式

程序使用项目现有的 Python/Windows 打包方式，基于 Python 标准库 `asyncio` 实现，无需为首版引入网络框架。产物为无界面 EXE，使用 Windows 任务计划程序以开机触发方式启动；任务设置为失败后重启。程序自身不创建系统服务、不自动修改防火墙，也不监听公网地址。部署人员使用管理员权限在 Windows 防火墙中仅对所选 TCP 端口放行受信任局域网来源。

启动命令接受一个 JSON 配置文件路径。配置中的 `listen_host`、`tcp_port`、`storage_root`、`allowed_networks`、`segment_max_bytes`、`read_buffer_bytes`、`idle_timeout_seconds` 和 `fsync_policy` 都可修改。`tcp_port` 为必填项，避免误监听不确定端口；`allowed_networks` 缺省时应拒绝启动，而不是接受任意来源。`idle_timeout_seconds` 的默认值为 `0`，表示不因空闲关闭连接。

## 组件与职责

### TCP 接收器

TCP 接收器只负责绑定、接受连接、验证来源 IP、读取字节和将字节交给会话归档器。每一条 TCP 连接对应一个会话，不把一次 `recv` 调用、固定超时或一次文件分卷误判为业务请求。接收缓冲区大小仅影响性能，不影响保存的字节序列。

来源 IP 不属于 `allowed_networks` 时，接收器在应用日志记录一条拒绝事件后立即关闭连接，不创建会话目录或原始负载文件。达到可配置的并发连接上限时，接收器同样拒绝新连接并在应用日志记录原因；已接受连接不受影响。若将 `idle_timeout_seconds` 设为正数，达到该时长仍未收到新字节的连接会被关闭、记录 `idle_timeout` 终态，已落盘字节仍然保留；设为 `0` 时不启用该行为。

### 会话归档器

每次接受连接时，归档器生成不可预测的 UUID 会话编号并创建目录：

```text
<storage_root>/incoming/YYYY/MM/DD/<session-id>/
  session.json
  events.jsonl
  payload-000001.bin
  payload-000002.bin
  ...
```

`payload-*.bin` 是原始字节文件。写入采用二进制追加模式，不插入分隔符、时间戳、编码转换或校验字段。将一个会话所有分卷按序拼接，必须逐字节等于该 TCP 连接从接受到关闭期间读取到的流。

`session.json` 在连接建立时创建，记录模式版本、会话 ID、本地监听地址、对端 IP/端口、建立时间和初始状态 `open`。它在关闭或恢复时以“写入同目录临时文件后原子替换”的方式更新状态、结束时间、总字节数、按文件名升序排列的分卷清单和当前完整流的 SHA-256。临时文件不得被 API 当成有效会话元数据。

`events.jsonl` 为追加式审计日志。连接、每次成功写入、分卷切换、空闲超时、I/O 故障、连接关闭和恢复操作各占一行 JSON。写入事件包含单调的事件序号、UTC 时间、当前分卷序号、该次写入在分卷中的起始偏移和字节数。来源拒绝与并发超限只写入应用日志，因为它们没有可归属的会话。事件日志服务于取证和未来边界解析，不是原始载荷的替代品。

文件达到 `segment_max_bytes` 时，归档器关闭当前分卷并在同一会话目录创建下一分卷；TCP 连接保持不变。为避免单个接收块被人为拆分，先将完整块写入当前分卷，再在下一次写入前执行分卷切换。因此相邻分卷边界只对应归档策略，不能解释为业务报文边界。

### 完成与恢复

对端正常关闭连接时，归档器冲刷文件、依据完整原始流计算 SHA-256、追加关闭事件，并原子更新 `session.json` 为 `closed`。异常断开按同一流程记录 `closed_abnormally` 与原因，已收到的字节仍可读取。

进程重启时，恢复扫描器查找状态为 `open` 或缺少终态的会话。它不删除、截断、重命名或改写任何 `payload-*.bin`；只重新计算已写字节数和 SHA-256、追加恢复事件、将会话标记为 `interrupted`。TCP 连接无法跨进程恢复，设备重新连接时会形成新会话。这保证断电或崩溃后仍能审计与保留已落盘部分，而不伪称这些字节构成完整请求。

`fsync_policy` 首版提供 `always` 和 `on_close`：前者每个写入块刷入磁盘，优先数据耐久；后者只在分卷和关闭时刷盘，优先吞吐。默认使用 `always`。

## 后续处理和 API 扩展点

接收器仅在一个写入块成功持久化后发布内部不可变 `RawDataPersisted` 事件，其中只含会话 ID、分卷、偏移、长度和路径。未来处理器通过该事件或扫描已完成会话工作，禁止直接读取 socket，也禁止修改归档目录中的原始文件。

将来的 HTTP API 作为独立组件绑定另一个配置端口，至少可提供会话列表、会话详情、分卷下载、按会话触发解析及解析状态查询。下载原始数据时应以 `application/octet-stream` 提供单分卷或按顺序拼接的流，并保持权限校验。API 实现不属于首版范围。

## 错误处理与可观测性

程序写入按日滚动的结构化日志，日志包含会话 ID 和错误类别，不记录原始数据正文。磁盘空间低于配置阈值、无法创建目录、写入失败或监听绑定失败均应记录明确错误并以非零退出；由计划任务负责重启。单个会话写入失败时，程序关闭该连接并继续服务其它会话，避免一台异常设备使监听器整体停止。

进程启动时校验目录可写、端口合法、来源网段合法、分卷/缓冲大小为正数且保存目录不位于临时目录。配置中的监听地址不得是 `0.0.0.0` 且来源网段为空；如需监听全部网卡，必须显式指定局域网 CIDR 白名单。

## 验收与测试

自动化测试使用 loopback TCP 客户端，验证：

1. 二进制、空字节、UTF-8、GBK 和任意长度数据的拼接结果逐字节一致。
2. 客户端多次写入但不断开时，服务保持同一会话且不会生成虚假的请求边界。
3. 正常关闭与异常断开均保留全部已写字节和正确终态。
4. 达到分卷阈值后，按序拼接所有分卷可复原完整 TCP 流。
5. 模拟未完成会话后重启，恢复器只新增元数据，不改动现有原始分卷。
6. 非白名单来源、无效配置、端口被占用和磁盘写入错误均有可诊断的失败结果。
7. 打包后的 EXE 可读取同目录配置，以任务计划方式后台启动并写入保存目录。

## 非目标

首版不尝试从未知字节流识别报文边界，不实现 FTP/UDP/HTTP 协议服务器，不解析 `.rot` 字段，不同步到 QMS/MySQL，也不删除、压缩或按内容合并原始会话。保留策略、业务解析规则和 HTTP API 在取得真实设备通信样本后另行设计。
